## Windows 清理诊断与建议

上一轮实际现象：所有用例输出后仍不退出，Ctrl+C才能结束；不能把该退出码算成功。

本地依赖源码证据：playwright/lib/runner/index.js 的 webServer 启动使用 shell:true；Windows 分支明确不支持 gracefulShutdown。playwright-core/lib/coreBundle.js 调用同步 taskkill /T /F 清理子进程树。原配置通过 npm→shell→npm→Vite 启动，涉及该路径。尚未捕获当时 taskkill 的输出，故只能将进程树清理列为疑点，不能声称已证明根因。

已准备并实测替代路径：preview-lifecycle.setup.ts 在 Playwright 主进程中调用 Vite preview API，返回 teardown 关闭 idle/all connections 与 HTTP server，无 npm/cmd 子服务；strictPort 4187，不复用占用端口。

执行 `npx playwright test --config tests/e2e/preview-lifecycle.config.ts`：1 项 HTTP 探针通过，测试摘要639ms，完整命令退出码0。没有调用浏览器、没有重建 A 的未完成页面、没有访问用户4174服务。该结果只证明无浏览器预览生命周期可正常退出；真实浏览器完整套件仍待放行验证。

建议 HQ 修改根配置（C 未修改）：将 build 作为 E2E 前置命令，移除 webServer，使用 globalSetup 引用本轮 setup，并将 baseURL 对齐4187。或者由 HQ 将 setup 端口统一为4173并同步 baseURL；保留 strictPort，避免错测旧预览。勿设置 reuseExistingServer:true 掩盖冲突，也勿依赖 Windows 不支持的 gracefulShutdown。
