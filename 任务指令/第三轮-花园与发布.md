# 第三轮：会生长的小花园与免费部署评估

用户要求：现有视觉太单调；加入花、树、河流和动态元素，休息后有奖励感；部署网站并说明国内外访问是否收费。不购买付费资源。

## A 执行 prompt

先读现有指挥日志、contracts、DESIGN，以及 frontend-design/ui-ux-pro-max 技能。在原 A 写入范围内升级真实 UI：src/ui/**、src/styles/**、public/art/**、DESIGN.md、handoffs/A.md。不改公共接口、数据引擎、根配置、PWA和依赖。

设计一个有完整构图的移动端“小河边的花园”，原生 SVG + CSS 可用，不用 emoji 拼贴。首页显著展示河流、树、草地、花朵、石头/小路和可识别的远近层次；克制的河流流光、树叶摇摆与花朵绽放。整体像一本可交互的自然图画，保留易读文案和清晰充电入口。不是在原页面上放一个小图标。

奖励规则：从 records 中 outcome=completed 的记录数量推导花园状态；每次完整休息贡献一朵花，达到3/7/14次有树苗/树冠等阶段变化（中文英文都需准确解释）。花朵显示可有上限，但文字总数必须准确。没有连续打卡、枯萎或提前结束惩罚。已完成但反馈跳过/负面依然有花；stopped 不计完成，但使用温和文案。旧记录自动映射，不新增持久化字段和v1结构。

完成后展示一次明确的花开/生长反馈，刷新或切换语言不重复触发奖励动画；动作计时保持稳定。支持暂停花园动态的可见控件，遵守 prefers-reduced-motion，所有自动循环动画都能停止，不用声音/震动。新增文案双语，夜间风格完整，320px、200%文字、键盘和触控保持可用。SVG装饰不污染屏幕阅读器，花园状态有可读文字。资源本地，无外部CDN，新依赖需先报告而不是安装。

先在 DESIGN.md 写简短设计决定再实现。补奖励计数/旧记录/停止与跳过反馈/语言切换/减少动画相关必要测试。尽量保留原流程按钮标签避免破坏既有验收。完成后发信并停写，由C真实浏览器验收。
